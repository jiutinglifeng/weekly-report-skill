# 周报助手（weekly-report）

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

一个用来写周报的 Skill：**不替你编，靠提问把你这一周问清楚**，再落成一份能直接粘进汇报系统的稿子。

适用于 Claude Code、WorkBuddy 等支持 `SKILL.md` 的智能体环境，纯 Markdown，无依赖、无脚本。

---

## 它解决什么问题

- **想不起来**：周一的事，周五已经模糊了。它不空问"你这周干了啥"，而是先对照上周待办，再按事件一件件引导。
- **计划写得像口号**："继续推进项目""加强协作"——领导看完不知道你要交付什么。它会把每项计划追问到"事项、产出、截止时间、优先级、依赖"五要素齐全。
- **技术岗写的周报领导看不懂**：`npm audit`、`CVE`、`前后端联调`这类词，换成"升级第三方组件、清理高危漏洞""打通页面与后台数据"。
- **格式每次都不一样**：固定结构 + 本地留档，积累下来可以纵向对比。

## 设计要点

**1. 按事件，不按天**
周报的骨架是"这周做成了哪几件事"，不是"周一周二各干了啥"。日期只是排序用的锚点，不要求逐日回忆，也不逼你凑满五天。

**2. 说人话**
写结果，不写手段。Skill 里带一张对照表，例如：

| 不要写 | 改写成 |
|---|---|
| 升级 npm 依赖，修复高危 CVE | 上线前统一升级第三方组件，清理全部高危漏洞 |
| 完成前后端联调、接口对接 | 打通前端页面与后台数据，页面内容可正常显示和更新 |
| 配置 DNS、SSL、CDN | 域名、证书、图片加速配置完成，站点可正常对外访问 |

原则：产品名、业务模块、业务数据可以写；框架名、包管理器、漏洞编号、命令行不写。

**3. 有提问预算**
每轮 3–5 个问题，总共不超过 3 轮就出确认稿。能合理推断的不问，带着假设直接写——让你改，比让你从头想要快。

**4. 文件是唯一真相**
周报先写进文件，再读取该文件原样展示。你粘进汇报系统的内容与本地文件逐字一致，不会出现"聊天里一版、文件里一版"。

**5. 中文命名**
生成的目录和文件一律中文：`周报/状态.md`、`周报/待办.md`、`周报/正文/2026年10月19日-10月23日.md`。不用拼音、不用缩写，打开文件夹就知道是什么。

## 岗位适配

第 3 步回忆本周工作时，按 `状态.md` 里的 `主职` 选一套线索包——只是提问的抓手，不改变流程骨架：

| 岗位 | 线索包内容 |
|---|---|
| **课程设计**（主职含"课程""教研""内容""培训"） | 课程处在立项/课纲评审/开发/上线/迭代的哪个阶段；这周产出的是课纲、课件、讲义、逐字稿、习题还是案例；拍摄、剪辑、配音、讲师对接；平台上线与课程改版；学员反馈与返修；院校、企业客户、内部业务方的需求沟通 |
| **通用**（其他岗位） | 上线交付、会议评审、临时任务、故障返工、学习培训、对外沟通 |

配套的三处细化：

- **产出按单位给数**：课程门数、章节数、课件页数、视频时长、题目数、课时数、完课率。拿不到数字就写交付物名称和状态，不编。
- **依赖给候选**：讲师档期、拍摄排期、剪辑、教研或专家评审、素材版权、平台上线配合，直接摆出来让人挑。
- **风险提醒**：讲师临时调档、评审延期、场地设备排期、素材授权未落地、需求方中途改方向。

兼任工作（课程设计师常兼行政、招聘、运营等）逐条列，标 `[兼任]`，排在主职事项之后。

想加自己的岗位，在「流程 → 3. 按事件回忆本周」里照同样格式加一组线索包即可，不用动流程。

## 安装

把整个 `weekly-report/` 目录（含 `SKILL.md`）放到下面任一位置：

```bash
# 方式一：用户级，所有项目可用
~/.workbuddy/skills/weekly-report/SKILL.md

# 方式二：项目级，只对当前项目生效
<你的项目>/.workbuddy/skills/weekly-report/SKILL.md

# Claude Code 用户把 .workbuddy 换成 .claude 即可
~/.claude/skills/weekly-report/SKILL.md
```

克隆安装：

```bash
git clone https://github.com/jiutinglifeng/weekly-report-skill.git /tmp/weekly-report-skill
mkdir -p ~/.workbuddy/skills
cp -r /tmp/weekly-report-skill ~/.workbuddy/skills/weekly-report
```

装好后可能需要重开会话，技能才会出现在列表里。

## 用法

直接说 **"写周报"**、"本周回顾"、"下周计划"即可触发。

首次使用会先给你一段使用说明，然后跟你确认三件事：报给哪家公司/团队、本周日期区间、这周最要紧的成果和最大的坑。之后每轮只问几个问题。

完整流程：

1. 读 `状态.md`，核对上周遗留待办
2. 按事件回忆本周：做成了哪几件事，每件做到什么程度、产出是什么、哪天完成
3. 问阻碍、风险、需要谁配合
4. 梳理下周计划，逐项补齐五要素
5. 出确认稿，只指出真正影响判断的缺口
6. 写入文件 → 读回 → 原样展示 → 更新待办清单

## 产出示例

```
周报/
├── 状态.md                          # 姓名、岗位、团队、周期偏好
├── 待办.md                          # 跨周维护的待办表
└── 正文/
    └── 2026年10月19日-10月23日.md    # 每周一份
```

周报正文结构（节选，示例人物为虚构）：

```markdown
---
姓名: 王敏
岗位: 课程设计师
团队: 某某教育科技
周期: 10月19日–10月23日
状态: 草稿
---
```

## 可调整的地方

Skill 是纯文本，直接改 `SKILL.md` 就能定制：

| 想改什么 | 改哪里 |
|---|---|
| 周期（比如按自然周、或月底统一报） | "工作区文件"一节里的周期说明 |
| 字数上限 | "写法与文风"一节的 800 字 |
| 周报栏目（加减小节） | "周报文件格式"一节的模板 |
| 文件命名语言 | "命名规则（强制）"一节 |
| 提问风格（更少或更多追问） | 铁律第 4 条的轮次限制 |
| 新增岗位线索包 | "流程 → 3. 按事件回忆本周"里的线索包 |
| 产出的计量单位 | "写法规则 → 写清产出"里的表格 |

## 打包分发

需要 `.skill` 文件时，把目录压成 zip 再改后缀：

```bash
zip -r weekly-report.skill weekly-report/
```
